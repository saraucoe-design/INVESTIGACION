This Model Card documents a methodological artifact built with synthetic demonstration microdata. Its purpose is to show that the proposed analytical workflow can be reproduced, audited, versioned, and tracked before authorized and anonymized institutional data are available.

Any predictions, performance metrics, confusion matrices, ROC curves, or other outputs generated by the current pipeline are **demonstration outputs only** and must **not** be interpreted as empirical findings about UNMSM, estimates of institutional performance, or evidence of causal effects.

# 2. Model Overview

This model demonstrates a reproducible Machine Learning pipeline for testing the technical workflow used to examine associations between digital transformation maturity, educational quality, and institutional efficiency. At the current stage, it is a reproducibility proof-of-concept rather than an empirical model of UNMSM.

The target variable is:

```text
high_quality_efficiency
```

The implementation accompanies the research project:

> **Digital Transformation and Its Relationship with the Quality and Efficiency of Higher Education: An Explanatory and Comparative Case Study of the Universidad Nacional Mayor de San Marcos**

The current version is intended exclusively for research-methodology demonstration, reproducibility testing, and educational experimentation. It is not intended to produce or communicate substantive research findings.

# 6. Training Data

The model was developed using a **synthetic demonstration dataset (600 records)** created solely to validate the reproducible ML pipeline. These records are not observations collected from UNMSM participants or organizational units.

Institutional context variables are based on publicly available UNMSM and SUNEDU information. No personal or confidential data are included. The synthetic microdata must be replaced by authorized, anonymized, and construct-validated institutional data before any substantive empirical interpretation.

# 14. Reproducibility

This model is integrated into a reproducible workflow using:

- Git
- GitHub
- DVC
- MLflow
- Python
- Scikit-learn

**Interpretation boundary:** the reproducible workflow is the research-methodology artifact being demonstrated. Reproducibility of a synthetic-data pipeline does not establish empirical validity of the substantive research claims.

**Transition to the empirical phase:** once ethics/institutional authorization is obtained, the synthetic microdata will be replaced by authorized and anonymized institutional data aligned with the validated construct operationalization and data dictionary. Only then may outputs be considered for substantive analysis, subject to the explanatory and comparative mixed-methods case-study design.

Pipeline stages:

1. Data preparation
2. Data validation
3. Model training
4. Model evaluation
5. Experiment tracking
6. Model versioning
